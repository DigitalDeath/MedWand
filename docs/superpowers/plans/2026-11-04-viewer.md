# MedicalWand Viewer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver the approved simulated capture application with a progressively reconstructed open cavity surface.

**Architecture:** Portable C++ core for snapshots, calibrated transforms and local reconstruction; Qt adapters for JSON and background work; Qt Widgets/OpenGL viewport. Hardware input is an explicit later integration.

**Tech Stack:** C++17, CMake, Qt6, small internal 3x3 Jacobi eigensolver, CTest. See implementation log for the dependency ruling.

**Spec:** ../specs/2026-11-04-point-cloud-viewer-design.md

## Global Constraints

- Pi 4 defines capabilities; OpenGL ES 2.0 common feature subset.
- Millimeters, radians internally, degrees in UI; right-handed coordinates.
- 100,000 raw captures; 20,000 filtered reconstruction points; 32 neighbors; 40,000 triangles.
- Preserve raw captures; simulated data labeled; real SPI unavailable until configured.
- One CPU worker; coalesce requests; stale results never replace newer data.
- No closed-solid/accuracy claim; measured coverage and inferred patches remain distinguishable.

## Review Focus

- Invalid and future-dated snapshots must not be captured.
- Dense duplicate samples must not create unbounded work or degenerate faces.
- Loading corrupt data must preserve the existing session.
- Undo/new/load during reconstruction must invalidate old results.
- Rendering errors must be visible rather than produce a blank successful viewer.
